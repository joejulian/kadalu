
= Upgrade Kadalu

Here the steps to upgrade a Kadalu service to the latest version for Kubernetes.

== Upgrade kubectl-kadalu binary

[source,console]
----
$ curl -fsSL https://github.com/joejulian/kadalu/releases/latest/download/install.sh | sudo bash -x
$ kubectl-kadalu version
[...]
----

== Apply the Kadalu operator manifest

1. Download the relevant Kadalu operator manifest for your Kubernetes cluster:
 - Generic Kubernetes: https://github.com/joejulian/kadalu/releases/latest/download/kadalu-operator.yaml[kadalu-operator.yaml]
 - MicroK8s: https://github.com/joejulian/kadalu/releases/latest/download/kadalu-operator-microk8s.yaml[kadalu-operator-microk8s.yaml]
 - RKE: https://github.com/joejulian/kadalu/releases/latest/download/kadalu-operator-rke.yaml[kadalu-operator-rke.yaml]
 - OpenShift: https://github.com/joejulian/kadalu/releases/latest/download/kadalu-operator-openshift.yaml[kadalu-operator-openshift.yaml]
2. Apply the manifest to the cluster. Do not rewrite values in the released
   manifest before applying it.

[source,console]
----
kubectl apply -f kadalu-operator.yaml
----

The operator owns the CSI node and controller workloads. A separate
`csi-nodeplugin.yaml` release asset is not used.

== Upgrade the controller workloads

Wait for the operator and CSI controller workload to finish rolling out:

[source,console]
----
kubectl -n kadalu rollout status deployment/operator
kubectl -n kadalu rollout status statefulset/kadalu-csi-provisioner
kubectl -n kadalu get pods
----

== Upgrade node plugins safely

The node plugin intentionally uses the `OnDelete` update strategy. Replacing a
node-plugin pod also terminates the Gluster FUSE clients running in that pod,
so do not delete every node-plugin pod at once.

Upgrade one node at a time during a maintenance window:

. Cordon and safely drain the node according to your workload disruption
  policy.
. Delete only that node's `kadalu-csi-nodeplugin` pod.
. Wait for its replacement to become Ready and verify the node's storage
  workloads before uncordoning it.
. Repeat for the next node.

[source,console]
----
kubectl cordon <node>
kubectl drain <node> --ignore-daemonsets
kubectl -n kadalu delete pod <nodeplugin-pod>
kubectl -n kadalu wait --for=condition=Ready pod/<replacement-nodeplugin-pod> \
  --timeout=5m
kubectl uncordon <node>
----

Choose drain flags appropriate for the cluster. Stop and investigate any mount
or workload failure before continuing to another node.
